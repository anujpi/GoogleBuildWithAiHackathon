## 2. What Is Fully Implemented

- The FastAPI skeleton. `GET /health` reports `loadedModels`, and the app starts without a model.
- The `POST /v1/predict/supply` code path: validation, the inference wrapper, the camelCase response with interval, evidence and provenance, and 422/503 handling. Tests cover it end to end with a synthetically trained model.
- Leakage-safe supply features: only t-1..t-3 are used, looked up by exact year, with no gap filling. Training and inference share them.
- The supply training/evaluation code:
  - chronological split, with an assertion that it holds
  - 3 baselines
  - XGBoost grid search with early stopping
  - an 80% interval calibrated on validation and checked on test
  - error analysis (by crop, season, year and district, plus the worst 10 predictions)
  - an artifact writer that will not overwrite
  - MLflow logging
- The `crop_yield.csv` loader and schema validator.
- Backend `MlClient` error mapping. The response parsing tolerates extra ML fields.

## 3. What Is Partially Implemented

- **Supply model: code exists, but there is no trained model.** No data, artifact or MLflow run exists in git or on this machine. No real metrics are recorded (there is no model card), so nobody can confirm that XGBoost beats the baselines. The test against the real artifact is skipped.
- **S01 cleaning:** `clean()` on its own rejects raw capitalised headers. Only `load_raw()` normalises them, and the test fails because of this.
- **Evaluation:**
  - The split is time-only. There is no spatial or unseen-district evaluation, although CLAUDE.md requires one.
  - The backtest uses the *final reported* area for year t, not planned/sown area. The results are optimistic, and this is not documented.
- **Inference edge case:** training drops rows where the t-1 yield is missing or zero. Inference accepts a t-1 production of 0: the lag becomes NaN and the request is not rejected.
- **Uncertainty:** one global interval width. It does not vary by crop, district or number of history years.
- **MLflow:** wired up but never run.
- **Provenance:**

- **Backend:**
  - The ML request is a provisional `Map` (§8).
  - `IntelligenceService` hard-codes the limitation "The model reports no uncertainty". That is no longer true.

## 5. ML API

### `GET /health`
`{status:"UP", service:"agri-ml", version:"0.1.0", environment, loadedModels:[modelVersion…]}`. Today `loadedModels` is `[]`.

### `POST /v1/predict/supply`
**Request** (camelCase, unknown fields rejected):
```json
{ "crop": "Potato", "season": "Rabi", "cropYear": 2015, "areaHectares": 10000,
  "history": [ {"cropYear": 2014, "areaHectares": 9800, "productionTonnes": 245000} ] }
```
**Validation:**
- `cropYear` must be 1950–2100.
- `areaHectares` must be greater than 0.
- `history` must have 1–3 items, each with `productionTonnes` ≥ 0.
- `crop` and `season` must exactly match the training categories (title-case S01 labels).
- History years must be unique and before `cropYear`, and must include `cropYear-1`.
- At least one history year must have a positive yield.

**Response 200:**
```text
modelName, modelVersion, dataClassification: "MODEL_PREDICTION",
prediction  { value, unit: "tonnes", period: "crop year 2015, Rabi season",
              interval { lower, upper, nominalCoverage: 0.8, method, testEmpiricalCoverage } | null },
evidence    { baselineValue, baselineMethod, historyYearsUsed },
provenance  { datasetVersion, featureVersion, trainedAt, trainingPeriod, evaluationPeriod },
generatedAt
```
**Errors:**
- 422: Pydantic list-format `detail`, or a string `detail` from `InvalidInputError`.
- 503 `{"detail":"supply model is not loaded"}`.
- There are no machine-readable error codes.

**Metadata:** read from the artifact's `metadata.json`. `datasetVersion` is `s01-<sha256 of raw CSVs>`.

**Coverage:**
- Spring Boot expects only `POST /v1/predict/supply`. It exists, but its request contract is incompatible (§8).
- Planned but missing: `/v1/predict/demand`, `/crop-suitability`, `/disease`, `/anomaly`.

## 7. Models

| Model | Status | Details |
|---|---|---|
| `supply-production-xgb` (served as `supply-xgb-v1`) | **Code implemented; no trained artifact** | Details below |
| Baselines: `naive_last_year_production`, `area_x_last_year_yield`, `area_x_mean3_yield` | **Implemented as evaluation comparators** | `area_x_mean3_yield` is also returned as `evidence.baselineValue`. None is served as a fallback |
| Demand, crop suitability/yield, disease, anomaly | **Planned only** | — |

`supply-production-xgb` in detail:
- **Target:** log(yield_t / mean yield t-1..t-3). Production is area × mean3 × exp(prediction).
- **Features:** log_area, log_area_ratio_lag1, log_yield_mean3, log_yield_rel_lag1..3, n_history_years, plus one-hot crop and season. There are **no region, weather or soil features**.
- **Training:** pseudo-Huber objective; grid of max_depth {2,3,4} × min_child_weight {5,20}; early stopping on validation; seed 42.
- **Metrics:** MAE, RMSE, WAPE and non-zero MAPE for validation and test, compared with the baselines. **No real numbers exist yet.**
- **Artifact:** `model.json`, `metadata.json`, `error_analysis.json`, `scored.csv`, plus an MLflow run.

## 8. Backend ↔ ML Contract Compatibility

**Request: incompatible.**
- The backend sends `{regionId:"ka", cropId:"tomato", horizonMonths:6}`. ML requires `{crop, season, cropYear, areaHectares, history}` and forbids extra fields. The result is a **422**, which `MlClient` turns into **502 `ML_SERVICE_ERROR`** on every call.
- **Semantics:**
  - The backend asks for a 1–12 month horizon for a region. ML predicts one crop-year and season for one district series.
  - The model takes no region input. The caller must supply the area and history, and **the backend has no such data**.
- **Ids:** the backend uses lower-case slugs; ML uses title-case S01 labels (`Potato`, `Rabi`).
- **Scope:**
  - The frontend offers mh/ka with onion/tomato/soybean. The default ML scope is UP with potato/wheat/onion/rice.
  - Tomato has no S01 production data.
  - A UP-trained model silently accepts inputs for other regions.

**Response: compatible, because the backend reads only a subset.**
- Exact matches: `modelVersion`, `prediction.value/unit/period`, `provenance.datasetVersion/featureVersion/trainedAt`.
- `value` goes from float to `BigDecimal`: fine. `trainedAt` is kept as a raw string: fine.
- **Dropped by the backend:** `modelName`, `dataClassification` (hard-coded), `prediction.interval` (the backend sets `confidence: null` and says "no uncertainty"), `evidence`, `trainingPeriod`/`evaluationPeriod`, `generatedAt` (the backend uses its own).

**Other differences:**
- **Units:** `"tonnes"` vs the `TONNES` enum in the contracts README.
- **Classification:** ML `ESTIMATED` vs backend `REGIONAL_ESTIMATE`. It is "resolved" in `ML_STATE.md`, but the backend enum was never changed.
- **Errors:**
  - ML 503 (model not loaded) reaches the client as **502**, not 503.
  - ML 422 and ML 5xx both become 502, so the backend cannot tell them apart.
  - ML has no error codes.

## 11. Current Blockers

1. No trained model (no data, artifact or MLflow run), so `/v1/predict/supply` always returns 503.
2. The S01 download needs a registered data.gov.in API key.
3. The MVP region and crops are not agreed. There are three conflicting scopes: the ML code (UP), `docs/dataset-catalogue.md` and `PROJECT_STATE` (Maharashtra), and the frontend (mh/ka, including tomato).
4. The backend request is incompatible with the ML schema, so every call returns 502.
5. There is no agreed supply contract (granularity, source of area and history, ids, units, uncertainty, error codes).
6. The backend has no historical area/production data, which the ML request needs.
7. 1 failing ML test, and no reproducible Windows environment (the lock is macOS-only).
8. No frontend consumer of `supply-forecast`.
9. Stale docs misstate the current state.
